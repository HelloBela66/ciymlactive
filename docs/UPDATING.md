Ця інструкція — для КОЖНОГО разу, коли в чаті з'являється новий файл
`polytsya-*.zip` (черговий milestone або fix). Виконуй кроки по порядку, не
пропускаючи — саме пропущені кроки й були причиною плутанини раніше (старий
`package.json`, відсутні пакети, непочищений кеш).

## 0. Постійна папка проєкту

Використовуй ОДНУ й ту саму папку весь час — не створюй нову для кожного
архіву (це змушує щоразу заново робити `npm install`, а це довго й нічого не
дає, якщо `.env` і так копіюється вручну). Зараз твоя робоча папка:

```
C:\polytsya-m10
```

Всюди нижче підставляй саме її (або нову назву, якщо колись перейменуєш
папку, — сама інструкція від цього не зміниться).

## 1. Розпакувати новий архів ПОВЕРХ цієї папки — обов'язково з `-Force`

Файл із чату завантажується в `Downloads` (за замовчуванням у Windows). Не
розпаковуй через Провідник ("Extract All") — він може мовчки пропустити
файли, які вже існують, і ти отримаєш суміш старого й нового коду. Замість
цього — в PowerShell:

```powershell
Expand-Archive -Path "$env:USERPROFILE\Downloads\ІМ'Я_АРХІВУ.zip" -DestinationPath C:\polytsya-m10 -Force
```

Заміни `ІМ'Я_АРХІВУ.zip` на реальну назву файлу (наприклад,
`polytsya-milestone-10-fix3.zip`). Прапорець `-Force` — головне: він
гарантовано перезаписує файли, що вже є, без запитань і без пропусків.

**Якщо PowerShell пише "не існує/невірний шлях"** — файл лежить не в
`Downloads`, а десь-інде (перевір, куди саме зберігає завантаження твій
браузер) — підстав правильний шлях замість `$env:USERPROFILE\Downloads\`.

## 2. Перейти в папку проєкту

```powershell
cd C:\polytsya-m10
```

Всі наступні команди виконуй саме тут.

## 3. Встановити/оновити залежності

```powershell
npm install
npx expo install --fix
```

Роби це щоразу, навіть якщо здається, що новий архів не додавав нових
пакетів — це не заважає і швидко (кілька секунд), якщо справді нічого не
змінилось.

## 4. Перевірити типи

```powershell
npx tsc --noEmit
```

- **Нічого не вивело** → все чисто, можна переходити до кроку 5.
- **Показало помилки** → скопіюй ВЕСЬ текст помилок (як є, з номерами рядків)
  і надішли в чат — не намагайся інтерпретувати сам, просто скопіюй-встав.

## 5. Повністю перезапустити застосунок

Це окремий, легко забутий крок — без нього телефон/Expo Go може й далі
показувати старий JS-бандл, навіть якщо файли на диску вже нові.

```powershell
npx expo start
```

А якщо `expo start` вже був запущений раніше в іншому вікні — НЕ покладайся
на те, що Fast Refresh сам підхопить усе (особливо нові екрани чи зміни в
порядку хуків) — натисни `r` прямо в тому терміналі, ЩЕ й додатково повністю
закрий і знову відкрий застосунок Expo Go на телефоні.

## 6. Перевірити фічу на пристрої

Тестуй саме те, що змінилось у цьому конкретному fix/milestone (зазвичай
описано в моєму повідомленні в чаті поруч із файлом).

## Про `.env`

Файл `.env` (ключі Supabase/ISBNdb/Google Books) НІКОЛИ не входить в архів —
він не в git навмисно (секрети). `Expand-Archive -Force` його не чіпає й не
видаляє (архів просто не містить такого файлу), тож повторно копіювати
`.env` в `C:\polytsya-m10` треба лише один раз — якщо він там уже є, він і
далі там залишається після кожного нового розпакування. Загубити його можна
хіба що видаливши папку цілком — сюди воно не відноситься.
