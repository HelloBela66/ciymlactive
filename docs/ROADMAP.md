# ROADMAP.md

## V1 (цей репозиторій, milestones 0-9)

Один користувач, безкоштовно, повністю офлайн-здатний core loop, українська мова.
Див. `PRODUCT.md` і milestone-таблицю в `ARCHITECTURE.md`.

## Milestone 11, доповнення — кураторська добірка + «Тренди» (виконано)

Власник продукту прямо попросив: (A) власну базу книг, яку можна поповнювати самостійно
(назва, автор, сторінки, обкладинка, жанр, мета читання), щоб вона одразу з'являлась і в
пошуку, і як перше джерело для «Що почитати завтра?»; (B) «Тренди» — топ-10 книг за кількістю
користувачів, що додали їх собі. Обговорено як концепт (детально нижче, в рядку
"Багато користувачів / Authentication") і свідомо розв'язано БЕЗ акаунтів — обидві фічі
цілком лягають на вже наявну анонімну інфраструктуру спільного каталогу (Milestone 8.2):

- **Кураторська добірка** — `curated_book` (Supabase, `supabase/schema.sql`), наповнюється
  ЛИШЕ через `service_role`-ключ і `scripts/sync-curated-books.js` з `data/curated-books.csv`
  (докладніше — `data/README.md`), ніколи з клієнта. Реалізує `BookMetadataProvider`
  (`CuratedCatalogProvider.ts`) — бере участь у звичайному пошуку й, першим (до Google
  Books-фолбеку), у «Що почитати завтра?» (`docs/BOOK_PROVIDERS.md`).
- **Тренди** — `catalog_top_books` RPC на вже наявних `catalog_book`/`catalog_book_device`
  (жодної нової таблиці), `app/trends.tsx` (докладніше — `docs/SHARED_CATALOG.md`).

## Явно поза межами V1 (розділ 47 ТЗ) — і що для кожного вже підготовлено архітектурно

| Майбутня функція | Що вже не блокує її додавання |
|---|---|
| Багато користувачів / Authentication | Repository-шар відокремлений від UI; додавання `user_id` — міграція, не переписування. Обговорено як концепт із власником продукту (Milestone 11, доповнення) разом із кураторською добіркою/Трендами/безпекою — рішення: акаунти РОЗВ'ЯЗУЮТЬСЯ ОКРЕМО й пізніше (спершу зроблено те, що не потребує їх — добірка + Тренди вище), і коли дійде черга — **опційний шар** (Supabase Auth, email+пароль, обов'язковий унікальний `@nickname`), не обов'язковий для всіх: local-first характер застосунку (`docs/LOCAL_FIRST.md`) лишається для тих, хто хоче лише персональний трекінг без входу. Акаунти потрібні насамперед як передумова для "Дует читання" нижче (соціальні функції), не самі по собі. |
| Subscriptions / Payments | Немає жодної paywall-логіки в коді, яку треба було б видаляти — додається як новий шар поверх існуючого. |
| Friends / Book clubs / Social feed | Дані користувача (нотатки/цитати/бібліотека) вже мають чіткі агрегати з ID — "поділитися" пізніше means нова таблиця видимості, не зміна існуючих. |
| Recommendation engine | Каталог (Work/Edition/Genre/Series) уже нормалізований і придатний для майбутніх ML/rule-based рекомендацій без переструктурування. Локальний крок уже зроблено й доповнено (Milestone 11) — «Що почитати завтра?» (`app/tomorrow.tsx`, `src/lib/tomorrowRecommendation.ts`): жанр+час+мета → одна книга, без повторів на тому самому пристрої. Спершу пробує кураторську добірку (розділ вище), лише тоді фолбек на Google Books. Свідомо БЕЗ крос-юзерної дедуплікації ("не пропонувати ту саму книгу іншому користувачу") — це прямо впирається в рядок "Багато користувачів / Authentication" вище, якого зараз (свідомо) ще немає. |
| «Дует читання» — двоє користувачів одночасно читають одну книгу й бачать прогрес/нотатки/цитати одне одного в реальному часі | Прямо запропоновано власником продукту як напрямок на майбутнє. Вимагає одразу двох речей, яких зараз немає: (1) Authentication/акаунти (рядок вище) — без стабільної ідентичності користувача нема кого "звести в пару"; (2) realtime-канал (Supabase Realtime поверх уже наявного `supabase/schema.sql` — природне продовження, а не нова інфраструктура) для живого прогресу читання, а не лише разового sync каталогу, як зараз. Дані самі по собі вже готові структурно: `reading_progress`/`note`/`quote` — саме те, чим і треба було б ділитись, лише зараз локальні. |
| AI-асистент | Нотатки/цитати/прогрес — вже структуровані дані, готові як контекст для майбутнього асистента, без спеціальної підготовки зараз. |
| Складна cloud sync / Supabase-каталог | `LOCAL_FIRST.md` + repository pattern — точка розширення визначена, не реалізована. |
| Publisher portal / marketplace / мікросервіси | Свідомо не проєктується зараз — передчасна складність без потреби. |

## Короткострокові рішення, які варто переглянути після кількох місяців реального використання

- Чи достатньо Zustand для UI-стану, чи знадобиться щось потужніше при рості features.
- Чи `paused_intervals` як JSON-текст залишається зручним, чи варто виносити в таблицю.
- Реальні патерни використання ISBN-сканера (M7) — чи вартий він утримання окремого
  camera-модуля, якщо користувач рідко купує фізичні книги.
