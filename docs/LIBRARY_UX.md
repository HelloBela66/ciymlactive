# LIBRARY_UX.md — Бібліотека: вигляд, сортування, швидкі дії

POLYTSIA V1.6, Фаза 1 (перша feature-фаза циклу, `docs/V1_6_SPEC.md`, IMPLEMENTATION ORDER п.3).
Цей документ фіксує точну поведінку екрана Бібліотеки (`app/(tabs)/library/index.tsx`), той
самий підхід, що й `docs/BOOK_CAPSULES.md`/`docs/RECALL.md`/`docs/STALE_READING_RECAP.md`.

## Мета

Бібліотека — уже статус-таби над `UserBook`-записами (Milestone 2). Фаза 1 додає:
перемикач вигляду список/сітка, сортування, дві "розумні" горизонтальні стрічки на вкладці "Усі",
long-press швидкі дії над книгою. Наскрізний принцип ТЗ Фази 1: "коли нова функція конфліктує з
простотою основного потоку — обирай спрощення" — звідси кілька свідомих "не зроблено" нижче.

## Вигляд: список / сітка

Перемикач у заголовку екрана (`HeaderIconButton`, іконка `grid-outline`/`list-outline`), стан —
`LibraryViewMode = 'list' | 'grid'` (`src/lib/libraryPreferenceStorage.ts`), персистується через
`expo-secure-store` (той самий підхід, що й тема застосунку), завантажується один раз при
монтуванні екрана.

- **Список** (`BookRow`) — обкладинка 40×58 + назва + автори + прогрес-бар (лише для
  `reading`/`rereading`), серце-іконка для улюблених.
- **Сітка** (`GridBookItem`) — 3 колонки (`GRID_COLUMNS`), обкладинка домінує, назва одним рядком
  під нею (до 2 рядків), серце-бейдж поверх обкладинки (не окремий колір — accessibility, статус
  не лише кольором), той самий прогрес-бар знизу.
- `FlatList` (не `ScrollView`+`.map()`, продуктивність — Milestone 8, аудит: бібліотека раніше
  монтувала абсолютно всі книги одразу) перемонтується через `key={viewMode}` при перемиканні —
  React Native не підтримує зміну `numColumns` "на льоту".

## Сортування

Кнопка "Сортувати" (іконка `swap-vertical-outline`) відкриває нижнє вікно `LibrarySortSheet` —
звичайний RN `Modal` (`transparent`+`slide`), без нової залежності bottom-sheet: сортування
потрібне нечасто, повноцінна бібліотека для однієї дії була б надмірною. 4 варіанти
(`LibrarySortOption`):

- **За замовчуванням** — на вкладці "Усі" книги зі статусом читання/перечитування зверху
  (`updatedAt` спадно), решта — за датою додавання спадно (`sortAllLibraryView`); на решті
  вкладок — просто порядок зі сховища.
- **Спочатку оновлені** (`updated`).
- **За назвою (А-Я)** / **За автором (А-Я)** — `localeCompare()` без явного локале-аргументу
  (свідомий вибір: багатоаргументна "ICU"-форма на Hermes залежить від того, чи зібрано рушій з
  повним пакетом Intl-даних, і на деяких збірках мовчки ігнорує локаль — базова форма підтримує
  кирилицю завжди).

Кнопка отримує маленьку крапку-індикатор (`showDot={sort !== 'default'}`), коли обрано не
дефолтне сортування — видимий сигнал "тут щось змінено", без побудови окремої системи фільтрів.
Персистується через ту саму `LibraryPreferenceStorage`.

## Фільтр за статусом

Один горизонтально прокручуваний рядок з 7 компактних чипів (`FILTER_ORDER`): Усі / Читаю / Хочу
прочитати / Відкладено / Прочитано / Перечитую / Не дочитав — кожен з іконкою ліворуч від
підпису. "Усі" — перша вкладка й default-стан екрана (Milestone 11, доповнення3, пряме прохання
власника продукту).

Це кінцева форма після кількох ітерацій (доповнення3-12 намагались розподілити чипи у РІВНО 2
рядки — вся та історія замінена, не доповнена): один рядок без переносу, зайве йде за межу екрана
й гортається, без стрілок чи індикатора скролу.

## Що свідомо НЕ тут

ТЗ Фази 1 згадує повнотекстовий пошук по бібліотеці й фільтр за жанром/бейдж лічильника активних
фільтрів — жодне з цього не реалізоване тут, свідомо:

- **Пошук по бібліотеці** — можливе уточнення пізніше, коли книг стане достатньо багато, щоб це
  було потрібно; для кількох книг одного користувача це передчасна складність. (Окремий Personal
  Search, `app/(tabs)/search.tsx`, вже покриває офлайн-пошук по кількох доменах — не по самій
  бібліотеці-як-списку.)
- **Фільтр за жанром** — жанри редагуються на Book Details (`GenreTagsSection`, Milestone 9), а
  не на екрані бібліотеки.
- **Окремий лічильник активних фільтрів** — замінений маленькою крапкою на кнопці "Сортувати"
  (див. вище): той самий сенс ("тут щось відрізняється від дефолту"), без системи фільтрів, якої
  в застосунку ще немає.

## Полиці

Горизонтальна стрічка карток полиць (`ShelfCard`) — ПЕРШОЮ, ще до табів статусу (Milestone 11,
доповнення: пряме прохання власника продукту, щоб полиці одразу впадали в очі при відкритті
вкладки). Порожній стан — короткий текст-запрошення створити першу полицю, не окрема секція.

## "Розумні" стрічки (лише на вкладці "Усі")

Дві горизонтальні стрічки (`LibraryCarousel`), обидві лімітовані до `CAROUSEL_LIMIT` книг (досить,
щоб було чим гортати, замало, щоб перетворити верх екрана на ще один повний список — повний
перелік лишається доступним через відповідну вкладку статусу):

- **"Давно чекають"** (`useWaitingLongest`) — книги зі статусом "Хочу прочитати", найстаріші за
  `addedAt` спочатку.
- **"Нещодавно завершені"** (`useRecentlyFinished`) — книги зі статусом "Прочитано", найновіші за
  датою завершення.

Обидва хуки незалежні від обраного сортування бібліотеки (власна `select`-логіка поверх того
самого запиту за статусом) — стрічки завжди показують "давно чекають"/"нещодавно завершені" в
тому самому сенсі, незалежно від того, яке сортування власник продукту обрав для основного
списку. Порожня стрічка повертає `null` — не лишає по собі порожнього місця в layout.

## Long-press швидкі дії

`BookQuickActionsSheet` — довгий тап по рядку/картці відкриває нижнє вікно з трьома діями:
"Додати/Прибрати з улюблених", зміна статусу (`ChipSelect`, усі статуси одним рядом), "Прибрати з
бібліотеки" (з підтвердженням через `Alert.alert` — м'яке видалення, записи щоденника й нотатки
НЕ видаляються, про це прямо сказано в тексті підтвердження).

Свідомо НЕ окрема кнопка "…" на кожному рядку — та сама логіка спрощення: 6-7 книг на екрані з
видимою кнопкою дій щоразу — зайвий візуальний шум для дії, потрібної рідко. Для тих, хто про
long-press не здогадається, лишається звичний шлях через Book Details.

## Accessibility

Усі елементи керування — `accessibilityRole="button"` + описовий `accessibilityLabel` (для рядків
книг — включно з відсотком прогресу, коли відомий). Індикатори статусу (улюблене, прогрес) — не
лише кольором (ТЗ ACCESSIBILITY: "status not encoded only by color") — серце-іконка окремо від
кольору фону, прогрес — числовий бар, не просто заливка.

## Бекап

Без змін — `viewMode`/`sort` зберігаються локально (`expo-secure-store`), як налаштування
пристрою, не як дані користувача для бекапу (той самий підхід, що й вибір теми застосунку).
