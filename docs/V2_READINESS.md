# V2_READINESS.md — повний огляд застосунку і план на V2 (2026-09-09)

Контрольна точка на прохання власника продукту: повне обстеження «Полиці» — що вже реально
працює, у якому стані дизайн, які проблеми лишились відкритими, і що конкретно вже готове
(архітектурно) для наступного великого кроку — V2 (багато користувачів). Це НЕ заміна
`docs/STATUS_V1.md`/`docs/SECURITY.md` (їхні знахідки нижче лише зведені й освіжені), а
ширший знімок стану на сьогодні + синтез для планування.

## 1. Коротко (TL;DR)

- Застосунок реалізує **весь core loop і майже весь Milestone 0-11** зі специфікації:
  каталог книг, бібліотека зі статусами й полицями, таймер читання, щоденник (нотатки/цитати/
  реакції), цілі й нагадування, статистика/Wrapped/TBR, резервне копіювання, онлайн-пошук
  (Google Books + платний ISBNdb + власна кураторська добірка), спільний каталог і "Тренди"
  через Supabase, обкладинки скрізь у застосунку.
- **Технічний борг, реально знайдений і виправлений під час цього обстеження:** 3
  проблеми в коді, доданому після попереднього аудиту (гонка паузи сесії, занижений вдвічі
  темп читання після перечитування, лічильник реакцій рахує видалені з бібліотеки книги) —
  усі виправлені в цій же сесії (`CHANGELOG.md`, "Milestone 11 (аудит fix2)"), плюс окремий
  фікс `HTTP 414` у `scripts/sync-curated-books.js` (реальна помилка, з якою власник продукту
  зіткнувся при спробі поповнити кураторську добірку).
- **Найважливіший ВІДКРИТИЙ ризик, ще не виправлений** (не з цього обстеження — вже
  задокументований учора, `docs/SECURITY.md`): платний ключ ISBNdb компілюється прямо в
  клієнтський білд і може бути витягнутий ким завгодно з розпакованого застосунку → необмежені
  платні запити від імені власника продукту. Рекомендований фікс готовий (Supabase Edge
  Function-проксі), але потребує розгортання на боці власника продукту (доступ до Supabase
  CLI/дашборду) — не зроблено автоматично в цьому обстеженні, розділ 7 нижче.
- **Найважливіша прогалина процесу:** `jest`/`npx tsc --noEmit` ніколи не запускались
  по-справжньому в жодній хмарній сесії розробки (немає доступу до npm-реєстру тут) — лише
  `tsc` реально запускався на машині власника продукту (і то знайшов кілька помилок, усі

  (SQL) взагалі без жодного тесту, хоча `docs/TESTING.md` описує такий шар як задуманий.
  Розділ 6.

## 2. Технологічний стек (поточний, звірено з `package.json`)

Expo SDK 57 / React Native 0.86.3 / React 19.2.3, TypeScript `strict: true` (`~6.0.3`),
Expo Router (file-based, typed routes), expo-sqlite (async) з власним migration-runner на

каталог/кураторська добірка/обкладинки — без акаунтів, без персональних даних). Повний
перелік і обґрунтування — `docs/ARCHITECTURE.md` розділ 1 (сам вибір стеку не змінювався,

## 5. Архітектура коротко

Шарувата, feature-based: UI → feature hooks → domain services (чисті функції, без React/SQL)
→ repositories (єдине місце, що знає SQL) → SQLite. Local-first: core loop (бібліотека,
таймер, прогрес, нотатки) повністю офлайн; мережа (пошук, спільний каталог) — необов'язкова
надбудова, тихо деградує без Supabase/API-ключів. Provider-модель для метаданих книг
(Google Books/ISBNdb/Спільний каталог/Кураторська добірка/Ручне введення — один інтерфейс,
`docs/BOOK_PROVIDERS.md`). Повний опис — `docs/ARCHITECTURE.md`, `docs/LOCAL_FIRST.md`.

## 6. Тестове покриття — реальний стан

13 файлів `src/lib/*.test.ts` покривають чисту доменну логіку (`readingPace`,
`finishPrediction`, `tbrEstimate`, `streaks`, `seriesOrdering`, `backupSerializer`,
`sessionTiming`, `bookStats`, `journalInvalidation`, `memoryCardMood`,
`tomorrowRecommendation`, `calendarGrid`, `isbn`, `pluralizeUk`) — усі виглядають коректними
при ручному читанні коду, жоден жодного разу не був реально прогнаний через `jest` у жодній
хмарній сесії розробки (немає доступу до npm-реєстру в цьому середовищі — підтверджено
повторно й у цьому обстеженні, `npm install` завершується `403 Forbidden`). Repository-шар
(увесь реальний SQL — 9 міграцій, десятки repository-методів, включно з приєднаннями, які
щойно виправлялись у цьому обстеженні) не має ЖОДНОГО автоматизованого тесту, хоча
`docs/TESTING.md` описує "Repository-тести (інтеграційні)" як задуманий шар. **Рекомендація
для V2:** налаштувати реальний CI (GitHub Actions — там є доступ до npm-реєстру, на відміну
від цього середовища) так, щоб `npm install && npx tsc --noEmit && npx jest` запускались на
кожен push/PR — це єдиний спосіб ловити регресії автоматично, а не покладатись на ручне
тестування власника продукту на реальному пристрої після кожної зміни.

> **Застаріло (POLYTSIA V1.5, з Фази 1):** саме ця рекомендація вже виконана — `.github/
> workflows/ci.yml` запускає typecheck/lint/tests на кожен push, і кожна фаза POLYTSIA V1.5

## 9. Дизайн-система

Токени (`src/design/tokens.ts`): spacing (4/8/12/16/24/32/48), radius (8/12/16/24/999),
typography scale (display32/title22/heading17/body15/caption13/micro11), світла й темна
палітри (WCAG AA перевірено окремо для темної теми, Milestone 8). Явний принцип: "спокійний,
преміальний, мінімалістичний UI... ніяких важких градієнтів чи тіней" — послідовно
витриманий у всіх компонентах, включно з найновішими (chips фільтра, картки полиць).
Спільні UI-компоненти (`src/components/ui/`): `AppText`, `Button`, `Card`, `ChipSelect`,
`CoverThumbnail`, `EmptyState`, `LabeledInput`, `QueryErrorState`, `ReadingProgressBar`,
`ScreenContainer`, `StarRating` — невеликий, послідовний набір, без дублювання стилів по
екранах. Доступність (accessibility) підтверджена в обох попередніх аудитах: ролі й підписи
послідовно є на всіх інтерактивних елементах.
