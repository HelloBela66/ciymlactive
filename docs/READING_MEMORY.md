# READING_MEMORY.md — «Цей день у твоєму читанні»

POLYTSIA V1.6, Фаза 3. Цей документ фіксує точну поведінку фічі, щоб вона не змінювалась
випадково в майбутніх фазах (п.28 ТЗ).

## Мета

Іноді повертати користувачу його власні читацькі спогади з цієї ж календарної дати у минулі
роки. Це не social-функція, не AI-summary, не зовнішній контент — лише локальні дані самого
користувача, ніколи не залишають пристрій.

## Джерела даних (derived model, без нової таблиці)

`OnThisDayMemory` (`src/types/onThisDay.ts`) — похідна модель, як і `ActivityEvent`
(`src/types/activityEvent.ts`): жодної persistent-таблиці, жодного власного стану для запису.
Один спогад = одна книга в одному минулому році цього самого дня, зібрана з:

1. завершені сесії читання (`reading_session`, `ended_at IS NOT NULL`) — сумарна тривалість і
   сторінки за ВСІ сесії цього дня цієї книги;
2. `user_book.started_at` — «Ти почав читати цю книгу»;
3. `user_book.finished_at` — «Ти завершив цю книгу»;
4. нотатки (`note`) і цитати (`quote`) — короткий preview, з пріоритетом (нижче);
5. оцінка (`rating`) — приєднується ЛИШЕ до спогаду, позначеного `finished` (не самостійна
   подія — рейтинг сам по собі не має "дня", лише книга-на-яку-він-поставлений).

`OnThisDayRepository.listByMonthDay` (`src/data/repositories/OnThisDayRepository.ts`) — один
SQL-запит (`UNION ALL`, той самий підхід, що й `ActivityHistoryRepository.listRecent`), а не
окремий запит на кожен рік. `src/lib/onThisDay.ts` — уся подальша обробка (групування,
пріоритети, spoiler-евристика) чистими, детермінованими функціями без БД/`new Date()`
усередині, той самий house-патерн, що й `finishPrediction.ts`.

## Правила вибору

**Пріоритет типу події** (коли в одному році кілька подій однієї книги): завершено → улюблена
думка/цитата щоденника → завершена сесія читання → почав книгу → (лише оцінка). Нижче число —
вищий пріоритет (`OnThisDayMemory.priority`, `src/lib/onThisDay.ts`).

**Пріоритет запису щоденника на картці** (коли книга того дня має кілька записів, показується
щонайбільше 3): улюблений → «момент» → «думка» → цитата → інше.

**Вибір primary-картки на Home**: найближчий минулий рік, у якому є хоч один спогад (1 рік тому
має пріоритет над 2+), у ньому — спогад із найвищим пріоритетом типу події. Решта (усі роки, усі
книги) — «Ще N спогадів».

## Високосний рік

Спогад від 29 лютого показується лише 29 лютого у високосний рік. Дата НІКОЛИ не переноситься
на 28 лютого чи 1 березня — `strftime('%m-%d', ...)` природно повертає `'02-29'` лише для рядків,
де фактично збережено 29 лютого, тож жодної спеціальної обробки в коді не знадобилось (покрито
тестом `src/lib/onThisDay.test.ts`).

## Часовий пояс

Усі дати в БД — ISO-8601 UTC TEXT. Календарна дата для порівняння — МІСЦЕВА (локальна дата
пристрою користувача), не UTC (`computeLocalOffsetModifier`, `src/lib/onThisDay.ts`): перед
`strftime('%m-%d', ...)` мітка часу зсувається на локальний offset (`getTimezoneOffset()`), щоб
сесія, що почалась пізно ввечері за місцевим часом, не "переїжджала" на сусідній UTC-день.
Покрито repository-тестом на межі опівночі (`src/data/repositories/OnThisDayRepository.test.ts`).

## Spoiler-безпека

Повноцінний "spoiler-safe mode" — окрема майбутня Фаза 12 ТЗ, якої на момент Фази 3 ще немає.
Тут — самодостатня спрощена евристика (`applySpoilerRules`, `src/lib/onThisDay.ts`): якщо книга
спогаду ЗАРАЗ активно читається/перечитується (статус `reading`/`rereading`) і запис щоденника
прив'язаний до сторінки, яка лежить ДАЛІ за поточний прогрес користувача — текст цього запису
ховається («Спогад приховано, щоб не забігати наперед»), решта картки (сесія/старт/фініш)
лишається видимою. Запис без прив'язаної сторінки ніколи не ховається — немає надійного способу
визначити його позицію. Для завершених книг фільтрація не застосовується (їх немає в мапі
`activePageByWorkId`, яка будується лише зі статусів `reading`/`rereading`).

**Коли Фаза 12 (повноцінний spoiler-safe mode) буде реалізована**, цю евристику варто замінити
на виклик спільної логіки замість власної — `applySpoilerRules` спроєктована як окрема, легко
замінна функція саме для цього.

## Home-пріоритет

На момент Фази 3 жодна з конкуруючих контекстних карток Home (stale reading / capsule due / goal
near completion / TBR recommendation, п.18 ТЗ) ще не реалізована в цьому мілстоуні (Фаза 4
додала саму «Капсулу книги» — `docs/BOOK_CAPSULES.md` — але БЕЗ окремої контекстної картки на
Home: точки входу капсули — Completion/Book Memory screens, не Home) — формального
"покажи щонайбільше одну контекстну картку" механізму немає, і додавати його заради єдиної наявної
картки було б передчасною складністю. Картка «Цей день у твоєму читанні» просто додається до
послідовності Home (`app/(tabs)/index.tsx`) після «Зараз читаєш» і перед «Мій щоденник»/«Що
почитати завтра?»/«Тренди», сама вирішуючи свою видимість. Коли з'являться конкуруючі картки,
сюди варто додати спільний пріоритетний механізм — з переліком, уже заданим п.18 ТЗ.

## Архітектура (коротко)

- `src/types/onThisDay.ts` — типи (`OnThisDayMemory`, `OnThisDayYearGroup`, `OnThisDaySummary`).
- `src/data/repositories/OnThisDayRepository.ts` — один SQL-запит, сирі події.
- `src/lib/onThisDay.ts` — чисті функції: побудова спогадів, вибір primary, spoiler-евристика.
- `src/features/on-this-day/useOnThisDay.ts` — React Query хук, `queryKeys.onThisDay.forMonthDay`.
- `src/components/home/OnThisDayCard.tsx` — компактна Home-картка.
- `app/on-this-day.tsx` — повний екран, згрупований по роках.

Інвалідація: наразі окремої явної інвалідації `onThisDay`-ключа після мутацій (нова сесія,
запис щоденника, завершення книги) не додано — ключ параметризований `'MM-dd'` (сьогоднішня
дата), а React Query за замовчуванням рефетчить при новому монтуванні/фокусі екрана, чого
достатньо для цього сценарію («спогад з минулого» не змінюється діями СЬОГОДНІ, окрім
рідкісного випадку редагування вже застарілого запису — прийнятний компроміс, той самий, що й
`activityHistory.recent`, яка також не має явної мутаційної інвалідації).
