# BOOK_PROVIDERS.md — Абстракція пошуку метаданих книг

## Інтерфейс

```ts
// src/data/providers/BookMetadataProvider.ts
export interface RawProviderBook {
  externalId: string;
  title: string;
  authors: string[];
  isbn10?: string;
  isbn13?: string;
  publisher?: string;
  publicationDate?: string;
  pageCount?: number;
  language?: string;
  description?: string;
  coverUrl?: string;
}

export interface BookMetadataProvider {
  id: 'google_books' | 'isbndb' | 'manual' | (string & {});
  displayName: string;
  isEnabled: boolean; // false для провайдерів без офіційного/дозволеного API, або без ключа
  // `signal` — React Query скасовує застарілий запит під час набору тексту (див. GoogleBooksProvider.ts)
  searchBooks(query: string, signal?: AbortSignal): Promise<RawProviderBook[]>;
  lookupByISBN(isbn: string): Promise<RawProviderBook | null>;
  getEdition(externalId: string): Promise<RawProviderBook | null>;
  normalizeBook(raw: RawProviderBook): NormalizedBookDraft; // -> Work+Edition draft, через Zod
}
```

`NormalizedBookDraft` — це проміжна, провайдеро-незалежна модель (Zod schema в
`src/types/bookDraft.ts`), з якої однаково будуються Work+Edition, незалежно від того, чи
дані прийшли з Google Books, ISBN-скану чи ручного вводу. UI (Search, ISBN scan) ніколи не
бачить сирий провайдерський JSON — тільки `NormalizedBookDraft`.

## Реалізовані у V1 (M7)

- **GoogleBooksProvider** — офіційний публічний REST API (`https://www.googleapis.com/books/v1`).
  Працює без ключа, але анонімні запити мають дуже маленьку квоту й реально ловлять HTTP 429
  (підтверджено на реальному пристрої) — необов'язковий `EXPO_PUBLIC_GOOGLE_BOOKS_API_KEY`
  (безкоштовний, з Google Cloud Console, див. `.env.example`) додається до кожного запиту й
  знімає це майже повністю. Безкоштовне джерело, перевіряється перед платним ISBNdb — див. нижче.
- **ISBNdbProvider** (`src/data/providers/ISBNdbProvider.ts`) — **платний** сервіс ISBNdb
  (від $14.99/міс, 5000 запитів/день, є 7-денний пробний період для тестування без оплати).
  Свідомо останньою в порядку показу й в ISBN-flow: перевіряється лише коли безкоштовні
  джерела (спільний каталог, Google Books) вже не дали результату — платний запит не
  робиться даремно, коли безкоштовне джерело й так знайшло книгу. Додано свідомо після того,
  як з'ясувалось: жодне безкоштовне офіційне джерело не покриває більшість українських видань
  малих/середніх видавництв (Книжкова палата публікує лише статистику, не пошуковий API; НБУВ
  ім. Вернадського не має відкритого API для зовнішніх застосунків).

  **З POLYTSIA V1.5 Фаза 1.1 (`docs/SECURITY.md`) провайдер більше не звертається до
  `https://api2.isbndb.com` напряму й не тримає платного ключа в клієнтському коді взагалі** —
  увесь виклик іде через `src/data/remote/isbndbProxyClient.ts` → Supabase Edge Function
  `supabase/functions/isbndb-proxy/` → ISBNdb (сам ключ живе лише там, як Supabase secret,
  докладніше — README.md поруч із функцією). `isEnabled` тепер обчислюється з Supabase-
  конфігурації ПЛЮС окремого явного, не секретного прапорця `EXPO_PUBLIC_ISBNDB_PROXY_ENABLED`
  (`.env.example`) — без нього поводиться як звичайний вимкнений провайдер (не в UI, не
  викликається), той самий принцип, що діяв і раніше з наявністю ключа напряму.
- **ManualBookProvider** — не мережевий; це той самий шлях, яким користувач сам вводить
  усі поля. Присутній завжди як гарантований fallback, `isEnabled: true` завжди.

## Прибрано з активного пошуку (Milestone 10 fix6)

**OpenLibraryProvider** — до Milestone 10 fix6 був активним, безкоштовним, без квоти
провайдером (`openlibrary.org/api`, `covers.openlibrary.org`, `search.json`) і перевірявся
першим серед зовнішніх джерел. Прибраний повністю на пряме прохання власника продукту —
`OpenLibraryProvider.ts` видалено, разом з усіма посиланнями на нього в UI (пошук,
сканування ISBN). `'open_library'` лишається дійсним значенням `BookSourceTypeSchema`
(`src/types/bookDraft.ts`) навмисно — книги, вже збережені раніше з цим джерелом (локально чи
в спільному каталозі), мають лишатись валідними записами назавжди, лише новий пошук ним
більше не користується.

## Спільний каталог (Milestone 8.2)

`SharedCatalogProvider` (`src/data/providers/SharedCatalogProvider.ts`) — не зовнішнє
джерело метаданих, а кеш раніше підтверджених результатів усіх інших провайдерів у власному
Supabase-проєкті користувача. Реалізує той самий `BookMetadataProvider`, тож бере участь у
пошуку/ISBN-скані як звичайний провайдер, але ПЕРШИЙ у порядку — дешевший і швидший запит,
і головне: саме він дає змогу не витрачати платний ISBNdb-запит повторно на книгу, яку вже
шукав чи додав собі інший користувач застосунку (пряме прохання користувача). Детально —
`docs/SHARED_CATALOG.md` (навіщо, як налаштувати власний Supabase-проєкт, модель безпеки,
схема). Без налаштованого `EXPO_PUBLIC_SUPABASE_URL`/`EXPO_PUBLIC_SUPABASE_ANON_KEY` —
`isEnabled: false`, решта пошуку працює так само, як до цієї фічі.

## Кураторська добірка «Полиці» (Milestone 11, доповнення)

`CuratedCatalogProvider` (`src/data/providers/CuratedCatalogProvider.ts`) — власна база книг
власника продукту: назва, автори, сторінки, обкладинка, жанри й мета читання проставлені
ВРУЧНУ (не вгадані з вільнотекстового запиту), через `data/curated-books.csv` +
`scripts/sync-curated-books.js` (докладніше — `data/README.md`). Реалізує той самий
`BookMetadataProvider`, тож бере участь у звичайному пошуку/ISBN-скані як звичайний
провайдер — одразу після `SharedCatalogProvider` у `ALL_PROVIDERS` (`src/data/providers/index.ts`):
той самий власний Supabase-проєкт, той самий пріоритет над платними зовнішніми джерелами.

Записи в `curated_book` (Supabase) НІКОЛИ не йдуть з клієнтського anon-ключа — на відміну від
`catalog_book`, для цієї таблиці немає жодної write-RPC взагалі, лише читання. Єдиний спосіб
додати/змінити рядок — `service_role` ключ (`.env.admin`, ніколи не EXPO_PUBLIC_*), яким
користується лише локальний скрипт власника продукту. Докладніше про модель доступу —
коментар над `curated_book` у `supabase/schema.sql`.

## «Що почитати завтра?» — кураторська добірка перша, Google Books фолбеком (Milestone 11)

`useTomorrowRecommendation.ts` (`src/features/tomorrow/`) — рекомендація нової книги за
жанром+часом+метою. Спершу пробує `recommendCuratedBooks` (кураторська добірка вище): жанр і
мета в ній проставлені вручну, тож збіг точний, мова завжди підтверджена (куратор сам це
знає), і жодного мережевого пошуку по зовнішньому API не потрібно. Лише коли для цієї пари
жанр+мета в добірці ще немає (чи вже вичерпано) жодного непоказаного кандидата — фолбек на
попередній каскад `GoogleBooksProvider`, без жодних змін від fix1/fix2 нижче.

Це вже друга ітерація підходу: перша версія (Milestone 11, до доповнення) викликала ЛИШЕ
`GoogleBooksProvider`, ніколи `ISBNdbProvider` — свідомо, щоб не множити на цю фічу платний
ризик `docs/SECURITY.md` (знахідка 🔴). Але реальний тест на пристрої показав: навіть після
двох послідовних виправлень (fix1 — гарантовано широкий запит лише за жанром; fix2 — каскад
мовної фільтрації нижче) вільнотекстовий пошук Google Books усе одно міг не дати жодного
результату для типового поєднання жанр+мета — власник продукту прямо попросив власну базу
замість третьої спроби патчити той самий Google Books запит. `ISBNdbProvider` і зараз НІКОЛИ
не викликається для рекомендацій — той самий ризик (знахідка 🔴) лишається чинним для
Google Books-фолбеку так само, як і раніше.

**Мовна фільтрація Google Books-гілки — каскад, не єдина перевірка (fix2).** Звичайний пошук
(`app/(tabs)/search.tsx`) лишається на суворій подвійній перевірці `isLikelyUkrainianBook`
("Українська пошукова політика" нижче, Milestone 7.1) — не чіпається. Але для «Що почитати
завтра?» реальний тест на пристрої показав: цей подвійний фільтр інколи відсіює геть УСІ
кандидати для типового жанру (мовна мітка Google Books для українських видань часто
відсутня чи неточна). Тут порожній результат гірший за менш певний, тож
`useTomorrowRecommendation.ts` пробує рівні від найсуворішого до найслабшого
(`pickLanguageTier`, `src/lib/tomorrowRecommendation.ts`): 1) `isLikelyUkrainianBook`
(мітка + кирилиця), 2) лише кирилична назва (`hasCyrillicTitle`, без вимоги до мітки),
3) без жодної мовної фільтрації — перший непорожній перемагає. Коли довелось відступити
далі рівня 1 — екран результату (`app/tomorrow.tsx`) явно показує "Мова видання не
підтверджена напевно", а не мовчить. Кураторська гілка цей каскад не використовує взагалі —
`languageConfidence: 'confirmed'` завжди, коли книга прийшла з добірки.

## Заготовки під українські книгарні — прибрані (Milestone 10 fix6)

До Milestone 10 fix6 тут існували сім файлів-заглушок (`YakabooProvider`, `KSDProvider`,
`BookYeProvider`, `BookUaProvider`, `RanokProvider`, `NashFormatProvider`, `BalkaBookProvider`)
з `isEnabled: false` — жоден з цих сайтів на етапі написання не надавав публічного,
документованого, дозволеного для автоматизованого доступу API. Вони так і лишались повністю
неактивними аж до аудиту (`docs/STATUS_V1.md`, п. 3.8) — ніде не імпортувались, ніде не
викликались. Власник продукту вирішив прибрати цей мертвий код повністю, а не тримати його
"про всяк випадок": файли й `disabledProviderFactory.ts` (спільна фабрика-заглушка, якою вони
й були, більше нікому не потрібна) видалені.

Якщо для якоїсь із цих книгарень з'явиться офіційний, дозволений API — новий провайдер варто
писати заново з нуля за зразком `GoogleBooksProvider`/`ISBNdbProvider`, а не відновлювати
видалені заглушки. До того часу єдиний дозволений шлях для книг з цих книгарень —
`ManualBookProvider` (URL джерела зберігається як `sourceUrl` вручну).

**Жорстке правило, без винятків**: жоден провайдер не обходить `robots.txt`, CAPTCHA,
автентифікацію чи rate limits. Якщо для сайту немає дозволеного API — провайдера для нього
просто не існує, доки ситуація не зміниться офіційно.

## Data provenance (п.19)

Кожна книга/видання, створені через провайдер, отримують запис у `book_source`
(`source_type`, `source_name`, `source_url`, `external_id`, `retrieved_at`) і, за потреби
точковості, — записи в `field_provenance` на рівні окремого поля (готово під майбутню
модерацію спільного українського каталогу: система зможе показати "яке джерело дало це
поле" та дозволити кураторам вирішувати конфлікти між джерелами).

## ISBN flow (M7, п.21)

`expo-camera` (`CameraView`, `barcodeScannerSettings: { barcodeTypes: ['ean13'] }`) →
1) пошук у локальній БД (може вже існувати) → 2) точний лукап у спільному каталозі
(Milestone 8.2, `SharedCatalogProvider.lookupByISBN` — якщо цей ISBN уже підтверджував
будь-хто інший, результат приходить із власного Supabase, і жоден зовнішній провайдер
взагалі не викликається) → 3) якщо там немає, по черзі кожен активний провайдер
(`app/isbn-scan.tsx`, `activeProviders()`: Google Books → ISBNdb, якщо `isEnabled`;
Open Library прибрано з активного пошуку в Milestone 10 fix6 — розділ вище) через
`findByIsbnWithFallback` — спершу точний `lookupByISBN`, а якщо він
пустий, резервний текстовий пошук самим ISBN як запитом (`searchBooks(isbn)`), приймаючи
лише результат, чий власний `isbn10`/`isbn13` дійсно збігається зі сканованим (щоб не
підхопити випадковий збіг за ключовими словами). Реальна знахідка з тестування: той самий
провайдер інколи не знаходить видання через власний спеціалізований ISBN-лукап, хоча те саме
видання є в його звичайному пошуковому індексі — і навпаки, тому пробуємо обидва шляхи для
кожного джерела, перш ніж переходити до наступного → 4) якщо нічого — екран "не знайдено" з
кнопкою "Шукати в Google" (відкриває звичайний веб-пошук за ISBN у браузері — не
автозаповнення, але швидкий спосіб знайти книгу на сторінці книгарні й скопіювати дані
вручну; докладніше — розділ нижче) і кнопкою переходу в ручне створення з попередньо
заповненим ISBN. Крок 2 — явне підтвердження користувача перед імпортом (`/import/review`),
ніякого автозбереження без перегляду.

## "Шукати в Google" — чому не автоматично

Реальний тест показав: звичайний веб-пошук Google за ISBN одразу знаходить сторінки
книгарень (Rozetka, Yakaboo, Prom) з повною інформацією, бо індексує весь інтернет — на
відміну від вузької бази "Google Books". Перевірено: чи можна автоматично витягти ці дані —
ні. У Rozetka є офіційний API, але лише для їхніх продавців (керувати власними товарами, не
для стороннього пошуку по каталогу); у Yakaboo немає продуктового API взагалі, лише
партнерська програма з посиланнями. Автоматичний скрапінг цих сторінок (чи то напряму, чи
через офіційний Google Custom Search JSON API + парсинг знайденої сторінки) — саме те, що
цей проєкт не робить без винятків (розділ вище). Кнопка "Шукати в Google" — дозволена версія
тієї самої ідеї: відкриває той самий пошук у браузері одним тапом, людина сама бачить і
копіює дані.

## Українська пошукова політика (Milestone 7.1)

Пряме прохання користувача після реального тесту: пошук і сканування ISBN мають знаходити
й показувати лише видання, які справді українською мовою — а не будь-яке видання книги
(оригінал, англійський переклад тощо), яке провайдер вважає релевантним запиту. Привід:
ISBNdb повернув реальний запис з `language: 'ukrainian'`, але `title` лишився англійським
("IF WE WERE VILLAINS (Ukrainian language)") — тобто мовна мітка від джерела сама по собі
ненадійна, її не можна використовувати як єдиний критерій.

Реалізація — два незалежні шари, жоден не єдиний:

1. **На рівні запиту до джерела, де це можливо**: `GoogleBooksProvider.searchBooks` додає
   `langRestrict=uk` до запиту Google Books API — джерело саме звужує видачу. ISBNdb такого
   параметра не має (чи він недокументований достатньо, щоб покладатись на нього) — для
   нього лишається лише шар 2.
2. **Клієнтський фільтр** (`src/data/providers/ukrainianFilter.ts`,
   `isLikelyUkrainianBook`/`filterUkrainianBooks`) — застосовується до результатів усіх
   провайдерів через `select` у `useProviderSearch` (екран пошуку). Умова — ОБИДВІ разом:
   мовне поле від провайдера каже "українська" (`uk`/`ukr`/`ukrainian`/`українська`, різні
   коди в різних провайдерів) І сама назва містить кирилицю (захист саме від випадку вище —
   не-кириличної назви з хибно проставленою міткою мови). Навмисно НЕ звужено до літер,
   унікальних для української абетки (і, ї, є, ґ) — багато цілком українських назв
   ("Кобзар", "Сонце") їх не містять; мета фільтра — відсіяти явно іншомовний текст під
   хибною міткою, а не розрізняти українську від російської.

**ISBN-скан — свідомий виняток**: фільтр застосовано лише до резервного текстового пошуку
у `findByIsbnWithFallback` (`app/isbn-scan.tsx`), НЕ до точного `lookupByISBN`. Точний лукап
повертає саме те видання, чий штрихкод користувач щойно відсканував з паперової книги в
руках — відкидати цей результат за мовною міткою немає сенсу (якщо мітка бреше, користувач
все одно бачить і виправляє дані на екрані підтвердження імпорту перед збереженням,
`/import/review`). Це той самий екран, де сталась реальна знахідка з "IF WE WERE VILLAINS" —
фільтр тут не запобіг би показу цього конкретного запису (він і був точним ISBN-лукапом), але
не дає йому засмічувати текстовий пошук за назвою для інших книг.

**Свідомо не зроблено (поки що)**: пріоритизація за конкретними українськими видавництвами
(користувач згадав "приоритет на украинские издательства") — жоден з підключених провайдерів
не дає надійного структурованого поля "країна видавництва", а вести власний список назв
видавництв ризикує або пропустити legit видавництва, або хибно виключити книгу з чистою
мовною міткою через незнайому назву видавця. Мовний фільтр вище — перший, надійніший крок;
список довірених українських видавництв — можливий наступний крок, якщо мовного фільтра
виявиться недостатньо на практиці.

## Чому "100% знаходить за назвою" неможливо гарантувати (без exceptions)

Дослідження під час M7 (реальне тестування + пошук альтернатив) показало: жодного
безкоштовного, офіційного, легального джерела з повним покриттям українського книжкового
ринку не існує. Книжкова палата України публікує лише агреговану статистику, не пошуковий
API; Національна бібліотека ім. Вернадського не має відкритого API для зовнішніх
застосунків; українські книгарні (Yakaboo, КСД тощо) не мають офіційного API (див. розділ
вище) — а обхід їхнього захисту заборонений цим проєктом без винятків. Google Books —
найкраще доступне безкоштовне джерело, але його покриття свіжих українських перекладів
нерівномірне. ISBNdb (платний) суттєво ширше — агрегує дані видавців і
дистриб'юторів по всьому світу — але теж не гарантує 100% і особливо для нішевих
малотиражних українських видань лишається неперевіреним (жодного способу протестувати без
реального платного/пробного ключа користувача). `ManualBookProvider` (ручне додавання, за
потреби пришвидшене кнопкою "Шукати в Google") лишається єдиним гарантованим шляхом для
будь-якої книги — саме тому він завжди `isEnabled: true` і завжди доступний як явна дія в
UI ("Додати вручну"), а не прихований запасний варіант.
