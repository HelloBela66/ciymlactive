пояснювати заново" документ, що й `docs/NEXT_READ.md`/`docs/MY_READING.md`/`docs/MEMORY_HUB.md`/
`docs/HOME_REDESIGN.md`.

"Зберегти core Home (Читаю/cover/progress/pages/minutes/Continue/today). Прибрати лише реальне
дублювання (3 recommendation cards → 1 entry). Empty state для нової бібліотеки з сильним CTA.

`docs/HOME_REDESIGN.md`).

## Проблема (аудит V1.6.1, Розділ 46 "First-Time User Experience")

Аудит зафіксував: у застосунку немає жодного onboarding/welcome-екрана — перше відкриття веде
одразу на Home. Що буквально бачить новий користувач із порожньою бібліотекою:

> «`HomeShortcuts` — 4 тайли РЕНДЕРЯТЬСЯ БЕЗУМОВНО... усі чотири ведуть на порожні екрани. Три
> рекомендаційні картки — теж рендеряться безумовно... Явний `EmptyState`... — єдиний явний
> заклик до дії для нового користувача — це один `EmptyState` унизу екрана, ПІСЛЯ семи інших
> секцій/карток вище... CTA не перший елемент на екрані.»

І далі: «чотири Home-shortcuts і три рекомендаційні картки одразу зустрічають нового користувача
назвами на кшталт "Мій читацький відбиток", "Капсула книги", "TBR reality check"... термінологія,
зрозуміла лише PRODUCT.md-читачу, не новачку без жодного пояснення в UI.»

(Цитата описує стан ДО Фаз 14-16 — на момент цієї фази вже лише 3 shortcuts і 1 рекомендаційна
картка, але сама проблема — безумовний рендер незалежно від стану даних — лишається чинною.)

## Рішення 1 — Progressive disclosure: shortcuts/рекомендація ховаються для порожньої бібліотеки

`HomeShortcuts` і `NextReadEntryPointCard` (`app/(tabs)/index.tsx`) тепер загорнуті в перевірку
`isLibraryEmpty` (`allBooks.length === 0`, з `useLibraryAll()`) — рендеряться, лише коли в
бібліотеці користувача є хоч ОДНА книга в БУДЬ-ЯКОМУ статусі. Для геть нового користувача (0
книг) обидва зникають повністю; щойно додана перша книга (навіть просто "Хочу прочитати", без
жодної сесії) — вони одразу повертаються. Контекстна картка (`HomeContextCard`) НЕ загорнута в
цю ж перевірку — вона й без того вже сама повертає `null`, коли жоден із п'яти кандидатів не
застосовується (`selectHomeContextCard`), що для порожньої бібліотеки завжди так (немає ні
активного читання, ні капсул, ні цілей, ні TBR) — додаткова умова тут була б зайвою.

**Що НЕ зроблено:** склад `HOME_SHORTCUTS` (Мій щоденник/Моя пам'ять/Статистика) не змінено.
Завдання цієї фази в дужках називає "(Journal/Memory/On This Day/Fingerprint)" — прочитано як
приклад КАТЕГОРІЇ ("глибокі фічі, не для першого екрана"), а не буквальний новий список: On This
Day вже має свій вхід (`/memory` §"Цей день у твоєму читанні", Фаза 16), Fingerprint — свій
(`/my-reading` → Fingerprint tile, Фаза 15). Замінити ними "Статистика" означало б тихо
скасувати ці вже задокументовані рішення без окремого продуктового запиту саме на це —
"progressive disclosure" тут реалізовано буквально: прогресивне РОЗКРИТТЯ (коли показувати
наявні shortcuts), а не перестановка пунктів (що саме показувати).

## Рішення 2 — Empty state для нової бібліотеки з сильним CTA

До цієї фази геть новий користувач бачив на Home генеричний `EmptyState` ("Зараз ти нічого не
читаєш." → "Обрати книгу" → `/library`), який мовчки припускає, що бібліотека вже НЕпорожня —
для справді нової бібліотеки він просто передавав проблему на екран глибше: `/library` сам має
СИЛЬНІШИЙ, конкретний порожній стан ("Бібліотека поки порожня." → "До пошуку" → `/search`,
`app/(tabs)/library/index.tsx`, `FILTER_EMPTY_TEXT.all`). Саме це аудит і фіксує як зайвий
проміжний перехід ("CTA не перший елемент на екрані").

Виправлення: для `isLibraryEmpty` Home тепер показує ТОЙ САМИЙ сильний CTA бібліотеки напряму
(буквально скопійований текст/дія, не новий вигадкий), без проміжного переходу. Для НЕпорожньої
бібліотеки без активного читання (`showEmptyState`) — попередня поведінка ("Обрати книгу" →
`/library`) лишається без змін.
