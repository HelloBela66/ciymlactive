# Кураторська добірка книг («Полиця», Milestone 11)

`curated-books.csv` — джерело книг, які власник продукту сам додає до бекенду
(`curated_book` у Supabase, `supabase/schema.sql`). Ці книги одразу з'являються і в
звичайному пошуку застосунку (`CuratedCatalogProvider`), і як перший, найточніший кандидат
для «Що почитати завтра?» (жанр і мета читання проставлені вручну, а не вгадані з
вільнотекстового запиту до Google Books).

Файл ніколи не читається самим застосунком напряму — лише `scripts/sync-curated-books.js`
завантажує його в Supabase через `service_role` ключ (докладніше — `.env.admin.example` і
коментар над таблицею `curated_book` у `supabase/schema.sql`).

## Формат колонок

| Колонка | Обов'язкова | Формат |
| --- | --- | --- |
| `id` | так | Унікальний слаг латиницею: малі літери, цифри, дефіс (напр. `dovzhenko-zacharovana-desna`). Використовується як первинний ключ — зміна `id` для вже завантаженої книги створить НОВИЙ запис, а не оновить старий. |
| `title` | так | Назва книги. |
| `authors` | так | Автор(и), через `;` (напр. `Ліна Костенко;Василь Стус`). |
| `isbn13` | ні | Лише цифри (можна з дефісами — скрипт їх прибирає). **Має бути унікальним по всьому файлу й по всій базі** (окреме UNIQUE-обмеження в БД, не пов'язане з `id`) — та сама книга не може мати два рядки з однаковим ISBN під різними `id`. |
| `isbn10` | ні | Те саме для ISBN-10, та сама вимога унікальності. |
| `page_count` | ні | Ціле число сторінок. |
| `cover_url` | ні | Пряме посилання на зображення обкладинки. |
| `description` | ні | Короткий опис (до 5000 символів). |
| `genres` | так, хоча б один | Назви жанрів через `;`, ТОЧНО як у списку нижче — інакше книга не потрапить у фільтр за жанром. |
| `purposes` | ні | Підмножина `light;cry;laugh;absorbed` через `;` — для чого читати (легке чтиво / поплакати / посміятись / захопитись сюжетом). Порожньо — книга просто не матиме переваги в сортуванні за метою, але лишається кандидатом за жанром. |
| `language` | ні | За замовчуванням `uk`. |
| `is_active` | ні | `true`/`false` (за замовчуванням `true`). `false` — книга лишається в базі, але прихована з пошуку й рекомендацій (зручно, щоб тимчасово прибрати запис, не видаляючи рядок із CSV). |

Порожнє поле — просто порожній рядок між комами (`,,`), лапки потрібні лише якщо значення
саме містить кому.

## Як завантажити зміни в базу

1. Заповни/онови рядки в `curated-books.csv` (Excel/Google Sheets → експорт у CSV, чи прямо
   текстовим редактором).
2. Скопіюй `.env.admin.example` у `.env.admin` і заповни `SUPABASE_SERVICE_ROLE_KEY`
   (Supabase → Settings → API → **service_role**, НЕ anon-ключ) — докладні застереження в
   самому файлі.
3. `node scripts/sync-curated-books.js` з кореня репозиторію.
4. Скрипт покаже підсумок: скільки рядків додано/оновлено/пропущено з помилкою (з поясненням
   чому саме) — жоден валідний рядок не блокується через один невалідний, включно з
   ISBN-конфліктами (нижче).

Видалення рядка з CSV НЕ видаляє книгу з бази автоматично (скрипт лише додає/оновлює) — щоб
прибрати книгу з показу, постав їй `is_active=false` і запусти скрипт знову.

### Задовгі `id` (>100 символів)

Якщо `id` генерується автоматично з повної назви книги, він може вийти довшим за 100 символів
(межа з валідації нижче) — типово одразу для десятків рядків, якщо так генерує весь інструмент.
Замість ручної правки рядок-за-рядком: `node scripts/shorten-long-ids.js` перед sync-ом.
Він акуратно обрізає такі `id` до ~90 символів (по межі слова, не всередині) і додає короткий
детермінований хеш-суфікс, щоб не зіштовхнути різні книги з однаковим обрізаним префіксом;
короткі `id` не чіпає. Оригінал файлу зберігається в `curated-books.csv.bak` про всяк випадок.
Після нього — звичайний `node scripts/sync-curated-books.js`.

## Типові помилки

**"isbn13 ... уже використаний у рядку N цього ж файлу"** — той самий ISBN двічі в самому
CSV, під різними `id`. Найчастіша причина — книгу додали, потім додали ще раз під іншим
слагом (забули, що вона вже є). Видали зайвий рядок або зміни `id` одного з них так, щоб
лишився один рядок на книгу.

**"ISBN уже використаний записом з id "X" у базі"** — рядок ще НЕ конфліктує сам із собою в
CSV, але ISBN уже зайнятий іншим `id`, який раніше потрапив у базу (найчастіше — той самий
`id`, під яким книгу синхронізували раніше, а потім слаг у CSV випадково змінили чи
розмножили). Два варіанти виправлення: (а) якщо це та сама книга — зміни `id` рядка в CSV на
той, що вказано в повідомленні (`X`), тоді наступний запуск ОНОВИТЬ наявний запис замість
спроби створити другий; (б) якщо це справді дві різні книги з однаковим ISBN (рідкість, але
буває — різні видання з передрукованим/помилковим ISBN видавця) — виправ помилковий ISBN.

Обидва типи конфліктів скрипт ловить і показує ЗАЗДАЛЕГІДЬ, до самого запису в базу — решта
файлу синхронізується нормально, конфліктний рядок просто пропускається з поясненням (не
потрібно вручну шукати дублікати в редакторі на кшталт Notepad++: рядки з однаковим ISBN
можуть виглядати геть по-різному текстово — різний регістр/пробіли/порядок колонок — а
скрипт звіряє саме нормалізоване значення ISBN, не текст рядка).
