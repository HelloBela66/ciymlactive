# `isbndb-proxy` — Supabase Edge Function

**POLYTSIA V1.5, Фаза 1.1** (`docs/SECURITY.md`, знахідка 🔴). Тримає платний ключ ISBNdb на
сервері — мобільний застосунок більше ніколи не бачить `ISBNDB_API_KEY` напряму.

Архітектура: `Мобільний застосунок → ця функція → api2.isbndb.com`.

Код функції — `index.ts` поруч (докладні коментарі про валідацію, таймаут, ліміт розміру
відповіді й rate limiting прямо в файлі). `isbn.ts` — навмисна часткова копія
`src/lib/isbn.ts` (Deno-рантайм не бачить `src/` мобільного застосунку, докладніше — коментар
у файлі).

## ⚠️ OWNER ACTION REQUIRED — розгортання

Це потребує Supabase CLI й дій у Dashboard власника продукту — жодна з них не може бути
виконана з цієї сесії (немає доступу до credentials/CLI на машині власника).

### 1. Встанови Supabase CLI (якщо ще не встановлено)

```bash
npm install -g supabase
```

### 2. Залогінься й прив'яжи CLI до проєкту

```bash
supabase login
supabase link --project-ref <твій-project-ref>   # Dashboard → Project Settings → General → Reference ID
```

### 3. Задеплой саму функцію

```bash
supabase functions deploy isbndb-proxy
```

(За замовчуванням Supabase лишає `verify_jwt = true` для нових функцій — саме так і має
лишитись, **не додавай `--no-verify-jwt`**: це перша, безкоштовна лінія захисту, що не пускає
геть анонімні запити без жодного Supabase-ключа до коду функції взагалі — докладніше в
коментарі на початку `index.ts`.)

### 4. Постав секрет — сам платний ключ ISBNdb

```bash
supabase secrets set ISBNDB_API_KEY=<твій_реальний_ISBNdb_ключ>
```

Це **єдине** місце, де цей ключ тепер живе (крім самого кабінету isbndb.com). Він НІКОЛИ не
йде в жоден `.env*`-файл репозиторію, не в `EXPO_PUBLIC_*`, не в git.

`SUPABASE_URL`/`SUPABASE_SERVICE_ROLE_KEY` (потрібні функції для rate-limit RPC,
`edge_rate_limit_check` — `supabase/schema.sql`) Supabase проставляє **автоматично** для
кожної Edge Function самого проєкту — ставити їх вручну не потрібно.

### 5. Застосуй оновлений `supabase/schema.sql`

Той самий процес, що й раніше (`supabase/schema.sql`, шапка файлу): Dashboard → SQL Editor →
New query → вставити **весь** файл → Run. Ідемпотентно, безпечно перезапускати. Новий розділ
у самому кінці файлу створює `edge_rate_limit`/`edge_rate_limit_check` — без цього кроку
функція просто працює без rate limit (див. "fail open" у коментарі `checkRateLimit` в
`index.ts`), а не падає.

### 6. Увімкни фічу в мобільному застосунку

Задеплоєна функція з ключем ще нічого не змінює в застосунку сама собою — потрібен окремий,
свідомий крок power-switch (`.env.example`, розділ ISBNdb):

```
EXPO_PUBLIC_ISBNDB_PROXY_ENABLED=1
```

Це **не секрет** (просто "0"/"1"), безпечно бути в клієнтському бандлі — навмисне рішення,
щоб зберегти той самий принцип, що діяв і раніше з `EXPO_PUBLIC_ISBNDB_API_KEY`: ISBNdb —
платне джерело, і власник продукту сам вирішує, коли воно увімкнене, а не "автоматично щойно
Supabase налаштовано" (це змінило б відоме й свідоме "востаннє в черзі, лише коли безкоштовні
джерела не дали результату" на неконтрольовану витрату платної квоти для будь-кого з
налаштованим `.env`).

### 7. Перевір

```bash
curl -X POST 'https://<project-ref>.supabase.co/functions/v1/isbndb-proxy' \
  -H "apikey: <твій anon-ключ>" \
  -H "Authorization: Bearer <твій anon-ключ>" \
  -H "Content-Type: application/json" \
  -d '{"op":"lookup","isbn":"9786171241493"}'
```

Очікується `{"book": {...}}` або `{"book": null}` (якщо такого ISBN нема в базі ISBNdb) —
ніколи текст самого `ISBNDB_API_KEY` в жодній відповіді.

## Після розгортання — прибери стару клієнтську конфігурацію

Якщо в `.env`/`.env.local` власника продукту досі є рядок `EXPO_PUBLIC_ISBNDB_API_KEY=...` з
доміграційних часів — його треба видалити (ключ у ньому все одно більше нізвідки не
читається кодом застосунку, `src/data/providers/ISBNdbProvider.ts` тепер викликає лише цю
функцію, але старий ключ у локальному `.env`-файлі краще прибрати, щоб не заплутатись і не
тримати платний секрет без потреби навіть локально).
